# 后续开发流程
本小白记录/学习文档

## 获取信息
1、1Panel面板查看更新日志，重点看有没有 "重构"，然后就是 "新增功能" -> "功能优化"等

2、查看变化
路由增删以 upstream_api_diff.py 为准，swagger_api_diff.py 提供字段级细节（swagger 注解有覆盖缺口，两者互补）
2.1、使用命令查看源码变化
```shell
cd 1panel/1PanelClient/ && conda activate conda-venv
python3 scripts/upstream_api_diff.py v2.3.1 v2.3.2
# 可选 [--module firewall] [--out report.md]
# 如果使用 [--out report.md] 会将报告文件变为未跟踪文件，需要注意删除
```
2.2、使用命令查看swagger变化
```shell
# 1、从升级到新版的面板导出 doc.json（文件名自动为 <面板版本>_doc.json）
cd 1panel/1PanelClient/ && conda activate conda-venv
python3 scripts/get-doc-json.py ../logs

# 2、对比查看变化（基线文件名为占位示例；现存最近基线是 ../archive/logs/1panel_api_doc_v2.3.0.json）
python3 scripts/swagger_api_diff.py ../archive/logs/v2.3.1_doc.json ../logs/v2.3.2_doc.json
```

## 开始适配
1、创建分支
```shell
git switch -c adapt/v2.3.2
```

2、正常开发：改代码、跑测试、提交（可多次提交，中间态没关系）
2.1、针对重点部分进行核对，发现问题可以进行网页抓包以辅助完成开发
```shell
git add -A && git commit -m "适配上游 v2.3.2 API 变更"
```

3、适配并验证完成后推送并PR
```shell
# 1. 推分支到 GitHub
git push -u origin adapt/v2.3.2

# 2. 创建 PR（base 是 main，head 是你的分支）
gh pr create --title "适配上游 v2.3.2" --body "变更摘要、验证情况"

# 3. 等 CI 跑完并查看结果（你 ci.yml 的 pull_request 触发器会自动运行）
gh pr checks

# 4. 全绿后 squash 合并并删分支
gh pr merge --squash --delete-branch
```
3.1、网页操作 
在`git push -u origin 分支名` 之后打开仓库页面，GitHub 会出现黄条 "adapt/v2.3.2 had recent pushes — Compare & pull request"，点进去建 PR，测试跑完后点绿色的 "Squash and merge" 按钮

## 发版
```shell
# 1、修改版本号
cd 1panel && NEW_VER=0.2.1
sed -i '' "s/MARKETING_VERSION = [0-9.]*;/MARKETING_VERSION = ${NEW_VER};/g" \
    1PanelClient/1PanelClient.xcodeproj/project.pbxproj

# 2、验证修改版本号：应输出 6
grep -c "MARKETING_VERSION = ${NEW_VER}" 1PanelClient/1PanelClient.xcodeproj/project.pbxproj

# 3、提交并推送 main
git commit -am "chore: 版本号 0.2.0 → ${NEW_VER}"
git push origin main

# 4、打 tag 推送，触发 Release IPA 工作流
git tag v${NEW_VER} && git push origin v${NEW_VER}
```
