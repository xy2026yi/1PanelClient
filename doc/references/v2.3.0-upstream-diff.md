## 2. 防火墙：API 全面重构（唯一 breaking，M1 专项主体）

### 2.1 端点对照表

**v2.2.5（客户端现行 15 端点）→ v2.3.0（29 端点）**

| v2.2.5 端点（客户端现状） | v2.3.0 对应 | 说明 |
|---|---|---|
| `POST /firewall/base`（无参，FirewallBaseInfo） | `POST /firewall/base` **带请求体 `{name}`** | 路由保留但契约全变：按后端名（system/forwarding/docker？）返回 `FirewallSubsystemStatus`；FirewallBaseInfo DTO 已删除 |
| `POST /firewall/search`（规则分页） | `POST /firewall/rules/search` | 统一进 rules 命名空间；请求体 `FirewallRuleInventory`（scope/families/actions/states/excludeChains 维度全新） |
| `POST /firewall/port`（端口规则增删改） | **语义已变**：`POST /firewall/port` = UpdatePanelFirewallPort（改面板端口白名单）；规则 CRUD 拆到 `/firewall/rules`（建）/`/rules/update`/`/rules/delete`/`/rules/reorder` | ⚠️ 同路径不同义，最危险的一处 |
| `POST /firewall/ip` | 并入 `/firewall/rules` 系列 | — |
| `POST /firewall/batch` | `/firewall/rules/delete`（支持批量）+ `/rules/adopt` | — |
| `POST /firewall/forward`（转发增删改） | `/firewall/forward/base` + `/forward/search` + `/forward/operate` + `/forward/enable` | 转发独立成子域，模型重构 |
| `POST /firewall/update/port` / `update/addr` / `update/description` | `/firewall/rules/update` | 合并为单端点 |
| `POST /firewall/filter/rule/search` / `rule/operate` / `rule/batch`（iptables 链规则） | **删除**。替代模型：`/firewall/rules/native/detail`（原生规则清单）+ `/rules/adopt`（纳管）+ `/rules/sync/preview` `/rules/sync/task` `/rules/sync`（同步） | 客户端近期 8 个 iptables 对齐 commit 的 `isInit/isBind` 门控口径整体作废——新模型用 `FirewallSubsystemStatus.isInit/isBind` + inventory `states: managed/adopted/external/drifted/protected` 表达 |
| `POST /firewall/filter/chain/status` | **删除**（信息并入 `FirewallSubsystemStatus` 与 `/firewall/settings`） | — |
| `POST /firewall/operate`（启停） | **保留** `POST /firewall/operate` | 语义待抓包核实 |
| `POST /firewall/filter/operate` | **保留** `POST /firewall/filter/operate` | 唯一原样幸存的 filter 端点 |

**v2.3.0 全新能力（客户端可排期跟进）**：
- `GET /firewall/settings` + `POST /settings/operate` + `POST /settings/whitelist`：三后端组（`FirewallSettings{system, forwarding, docker}`）设置面板
- `/firewall/rules/reset` / `/rules/native/detail` / `/rules/adopt` / `/rules/sync/*`：规则纳管-同步生命周期
- **Docker 端口守护 6 端点**（`/firewall/docker/ports|endpoints|sync|operate|policies/batch|policies/delete/batch`，DTO 10 个 `DockerPortGuard*` 类型）：容器发布端口的防火墙策略管理——对新客户端是高价值新功能素材

### 2.2 DTO 层规模

- v2.2.5 `dto/firewall.go`：13 类型 / 100 行 → v2.3.0：**40 类型 / 362 行**，类型名几乎零重叠
- 关键新形状：
  - `FirewallSubsystemStatus`：`name/backend/isExist/isActive/isInit/isBind/version/pingStatus/ipv4/ipv6(FirewallBackendFamilyStatus)` —— 旧 base 信息的超集，一个类型承担状态+初始化+绑定
  - `FirewallSettings`：`system/forwarding/docker` 三组 `FirewallBackendGroup`
  - `FirewallRuleInventory`：分页 + `scope/families/actions/states/excludeChains` 筛选维度（`states` 枚举 managed/adopted/external/drifted/protected 是新模型核心概念）

## 3. 其他模块（按价值排期，无破坏）

### 3.1 终端会话管理（对应「SSH 会话保留与断线恢复」）
新增：`POST /terminal/sessions/search`、`/sessions/close`、`/sessions/closeAll`（+内部 `/internal/terminal/sessions/revoke`）。
客户端 `SSHSessionsView`（SSH 服务管理的会话页）现走 WebSocket 实时流；新端点提供 REST 查询/批量关闭，可作为会话页的补充分页来源（P2 跟进项）。

### 3.2 告警
`POST /alert/config/status`：单条配置启停。客户端 `AlertNotificationView` 行内 toggle 可接此端点免弹窗（P3 小项）。

### 3.3 文件
`POST /files/wget/process/remove`、`POST /files/move/stop`：下载记录清理 + 移动中断。`FilesOperations` 的 wget 进度面板与批量移动可补「清除记录/取消」按钮（P3）。

### 3.4 AI / 模型 / GPU（changelog 大篇幅，API 层零影响）
`agent/app/dto/ai*` 全部文件 **diff 为零**——llmman 供应商、DashScope 文生图、昇腾镜像/模板均为配置字符串层面的新增，客户端现有模型解码零破坏；GPU 监控新芯片（昇腾 910B/AMD）在 utils 采集层，响应字段是否新增需真机抓包核实（模型全可选化下安全）。
